# SDR round 2 and email personalization upgrade — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the second SDR issues list (16 items) and the content writers' email and call-script
upgrade (16 items), accuracy first.

**Architecture:** Additive changes on branch `fix/sdr-data-accuracy`, grouped into six workstreams
that touch disjoint files, so they can run one after another here or side by side in their own
worktrees. One migration (`0076`). Every rule that decides what a customer is charged or what a
buyer reads is a deterministic check with a test, never a prompt request alone.

**Tech Stack:** FastAPI + async SQLAlchemy (Postgres RLS, SQLite tests), React 18 + TypeScript,
Parallel Decisions for checks, the existing LLM chain for drafting.

## W1. Accuracy: industry and domain (SDR item 1)

- [ ] **1.1 Industry check for every new company, multi-industry aware.** `prospecting/industry_check.py`:
  one Parallel Decisions request per delivered company that is not already checked (LinkedIn,
  database, shared, web rows; Parallel rows already are), asking per ICP industry
  `operates_in_i: yes | no | unknown` (a company can be in several) plus `primary` and `supplier`.
  Kept on the account: `industry` = the strongest ICP industry it operates in, `custom_fields.
  industries` = every one it operates in, cited (`field_sources`). Refused: none at 0.7 or more →
  `wrong_industry`; only `supplier` and the ICP excludes suppliers → `wrong_industry`.
  $0.001 each, cached 90 days by domain. Off with no Parallel key (as today).
  Files: create `nexus/prospecting/industry_check.py`; modify `nexus/prospecting/deliver.py`
  (before the gate, after `_industry_from_evidence`); test `tests/test_industry_check.py`.
- [ ] **1.2 The gate reads every industry.** `relevance/gate._industry` passes when ANY of
  `custom_fields.industries` is an ICP industry. Test in `tests/test_icp_gate.py`.
- [ ] **1.3 Domain: vet every non-LinkedIn row too.** Web and shared candidates go through
  `vetting.vet` and `lands_elsewhere` like LinkedIn and Parallel rows. `deliver.py`.

## W7. Email and call-script personalization (content writers' 16 items)

Files: `nexus/agents/copy.py`, `email_quality.py`, `messaging.py`, `call_script.py`,
`personalization/brief.py`, `engagement/drafting/context.py`, `agents/facts.py`.

- [ ] **7.1 (1) A "what we do" line**: the value prop's description reaches the prompt;
  `STRUCTURE_RULE` asks for one plain sentence of what the product is.
- [ ] **7.2 (2) Problem as hypothesis**: "teams that go from X to Y usually find Z breaks first",
  never a claim about them.
- [ ] **7.3 (3) No literal examples in rules** (subjects, CTAs): described, not quoted.
- [ ] **7.4 (4) AI tells banned** in the prompt AND `BANNED_PHRASES` ("I came across",
  "impressive", "streamline", "seamless", "I'd love to", ...).
- [ ] **7.5 (5) One rule for activity**: reference the idea, never quote the post (`brief.py` and
  `SIGNAL_RULE` agree).
- [ ] **7.6 (6) Never cite size or revenue bands** (rule + check).
- [ ] **7.7 (7) One anchor signal**: picked once, it drives the hook, `select_value_prop` (by
  `signal.kind`, with stopwords) and `trigger_signal_id`.
- [ ] **7.8 (8) Gate bugs**: a greeting is a word ("Hi", "Hello", "Hey", "Dear", "Good morning"),
  not a prefix; the retry shows the failed draft.
- [ ] **7.9 (9) Fact verifier**: every number and capitalised name in a draft must appear in the
  prompt's context (allowlist: weekdays, months, contact, sender, company); a miss costs one retry,
  and on an automatic send holds the draft.
- [ ] **7.10 (10) Seeded shape per contact**: `hash(contact_id)` picks opener, CTA and subject
  style from a few each; logged on the message.
- [ ] **7.11 (11) Role matching**: whole-word, function AND seniority ("Vice President" is not
  "president", "Product Owner" is not "owner").
- [ ] **7.12 (12) Fit reasons and research highlights** reach the prompt, three lines at most.
- [ ] **7.13 (13) Call script sender and safe fallback**: no `<your name>` placeholders, no banned
  phrases in the fallback.
- [ ] **7.14 (14) Call script check**: opener and voicemail length caps, banned phrases, one retry.
- [ ] **7.15 (15) Permission opener and first-reaction branches** ("who's this?", "send an
  email", "I'm busy") tied to the value prop's pains.
- [ ] **7.16 (16) Optional P.S.**: a separate field, off by default, shown to the rep with a
  "I confirm this is true" tick before it can be sent.

## W8. A full ICP per service (SDR item 5)

Owner decision 2026-10-29, superseding "one ICP/offer per workspace" (2026-10-28): **each service a
company sells gets its own ICP** (industries, size, countries, buyer titles, value props, product
context), its own Populate and its own daily discovery, and a campaign pitches one service.

- [ ] **8.1 Services as rows**: migration `0077_icp_services` (`icp_services`: tenant-scoped, name,
  source URL, `icp` JSON, value props, product context, daily target, archived). The workspace's
  existing profile is the default service, so nothing moves for a workspace that adds none.
- [ ] **8.2 Draft a service from its page**: "Draft from page" reads a route such as
  `/services/abc` (not only the homepage) and fills that service's ICP; charged as
  `ai.icp_from_website`.
- [ ] **8.3 Per-service Populate and daily discovery**: both take a service; `find_icp_companies` and
  `deliver` already take an ICP dict. An account records which service found it.
- [ ] **8.4 A campaign picks its service**: drafts, Find contacts titles, call scripts and the fit
  shown use that service's ICP and value props.

## Decisions (owner, 2026-10-29)

- **Services**: a full ICP per service (W8).
- **Credits**: charge only for a result (W2), and add **"Search another domain"**: a user types a
  domain for a contact whose company receives mail elsewhere; the finder runs there and charges
  `enrich.contact` only when it keeps an address.
- **Industry**: check every new company (W1), **LinkedIn first**: the LinkedIn company record we
  already hold in the shared store, then the LinkedIn company actor (Apify, the route the product
  already uses), then the Parallel check for what is still unproven. linkedin.com itself is never
  fetched by our own crawlers: LinkedIn bans scrapers and serves bots a login wall, and the codebase
  has kept to that since the jobs dork.
- **Execution**: side by side. Here: W1, W2. Own sessions, each on its own branch off this one:
  W7 (copy), W5 minus 5.2 (records and housekeeping, migration `0076`), W3 + 5.2 + 6.1 + 6.4 (tasks,
  history, unified inbox), 6.2 + 6.3 (mailboxes table, call console), W8 + W4 (service ICPs and
  titles, migration `0077` parented on `0075` and re-parented onto `0076` at merge).
